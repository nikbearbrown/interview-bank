1. Define the agent's contract: a ticket comes in, the agent produces a structured plan (classification, intended reply approach, which docs it will consult, and the exact write it intends to make), and nothing is written until a human approves that plan. Decide the plan schema (Pydantic model) and the states a ticket moves through: received, planned, awaiting_approval, approved, executed, rejected.
2. Add a planning step in `app/triage.py` that calls Claude using the Anthropic SDK with a system prompt that forbids acting, and forces a structured JSON plan via a tool schema (category billing/bug/how-to, confidence, relevant doc names, proposed reply outline, and the planned `save_reply` call). Keep this step strictly read-only: it may read the ticket and the `docs/` articles but must never call `save_reply`.
3. Give the planner a way to find the right help articles from the 40 docs, for example a simple keyword or title index loaded at startup passed to Claude, or a retrieval tool Claude can call, so the plan cites specific articles rather than guessing. At about 600 words each the articles may be small enough to include selectively in context, with prompt caching for the stable portion.
4. Persist each plan with its state (a small `plans` table next to the replies table, written through the existing database layer), and add two endpoints in `app/api.py`: `POST /triage` now returns the plan and a plan ID with status awaiting_approval, and `POST /triage/{plan_id}/decision` accepts approve, reject, or edit from a human reviewer. Protect the decision endpoint with a reviewer credential read from an environment variable in `config.py`.
5. Build the execution step so it only runs for an approved plan: it re-reads the stored approved plan (including any human edits), calls Claude to draft the reply constrained to that plan, then calls `save_reply(ticket_id, text)` once. Make it idempotent and reject execution if the plan is not in approved state, if it was already executed, or if the ticket changed since the plan was made.
6. Add safeguards: validate Claude's plan output against the schema and retry or fail closed on malformed output, handle SDK errors and timeouts with bounded retries, expire stale pending plans, and log every state change (who approved, when, what changed) for auditing. Keep the API key and reviewer credentials in environment variables only.
7. Write pytest tests with Claude mocked: the plan step never calls `save_reply`, execution refuses unapproved, rejected, or already-executed plans, edits by the reviewer are honoured, malformed model output fails closed, and the endpoints return the expected states. Add a few evaluation cases of real-looking tickets for each category to check the classification and the cited docs.
8. Update the container configuration and docs: confirm the single container still works with the new table and environment variables, add a short help article or README section explaining the approve-then-execute flow, and do a manual end-to-end run (submit a ticket, review the plan, approve, check the saved reply) before release.
