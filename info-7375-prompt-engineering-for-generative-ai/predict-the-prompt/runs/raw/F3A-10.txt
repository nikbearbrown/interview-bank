1. Define the target behavior and a success measure: the reply must be grounded in the help articles in `docs/`, cite which article it used, and say "I don't know, escalating" when no article covers the ticket. Build a small labeled set of past tickets with the correct article(s) to evaluate against.
2. Add a loader that reads the 40 markdown articles at startup, splits each into sections of a few hundred words (about 600 words per article is small, so section-level chunks keep the context tight), and keeps the title and file name as metadata.
3. Build the retrieval step in a new module used by `app/triage.py`. Start with a simple keyword/BM25 ranking in pure Python (no new services, since it deploys as one container), and only add embeddings if the evaluation shows keyword search misses too many tickets.
4. Make retrieval take the ticket text plus the classification (billing / bug / how-to) and return the top 3 sections above a minimum score. Return an empty result if nothing scores well enough, rather than the best bad match.
5. Change the Claude call that drafts the reply so it receives the retrieved sections in clearly delimited blocks, with instructions to answer only from them, quote or reference the article name, and fall back to a "needs a human" reply when no section is supplied or none answers the question. Keep the ticket text in a separate block, marked as untrusted customer input.
6. Make `save_reply(ticket_id, text)` safe to use with the new flow: store the cited article names alongside the reply, and do not write a grounded-looking reply when retrieval was empty. Keep the secrets and settings in `config.py` (top-k, score threshold, model name) so they can be tuned without code changes.
7. Add pytest tests in `tests/` for the loader, for retrieval (a known ticket returns the expected article; gibberish returns nothing), and for the triage flow with the Claude client mocked, checking that the prompt contains the retrieved text and that the empty case takes the fallback path. Run the labeled set against the real model once and compare grounded-answer accuracy with the old behavior.
8. Check `POST /triage` end to end with a few sample tickets, log which articles were retrieved for each ticket for later debugging, and ship in the same container with the docs folder included in the image.
