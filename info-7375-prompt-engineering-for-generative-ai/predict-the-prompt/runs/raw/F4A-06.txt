1. Define the agent's job and limits: it receives a ticket and the classification categories (billing / bug / how-to), and its first output is a written plan, never an action. The plan lists the steps it intends to take, which docs it expects to need, and whether the ticket needs a human, before any tool is called.
2. Add a planning stage in app/triage.py: one Claude call (Anthropic SDK, structured JSON output) that reads the ticket and returns a plan object with the predicted category, a confidence value, the docs to look up, and the ordered steps. Validate this plan against a schema, and reject or retry it if it is malformed.
3. Give the agent read-only tools for the execution stage: a tool that searches the 40 docs in docs/ (simple keyword or embedding index built at startup) and a tool that returns the text of a chosen article. Keep save_reply out of the tool list so the planning and research stages cannot write to the database.
4. Add an execution stage that follows the approved plan step by step: look up the planned articles, classify the ticket, and draft a reply grounded in the retrieved text. Check after each step that the result still matches the plan, and if it diverges (for example the category changes), go back to the planning stage with the new evidence.
5. Add a check step before any write: a second Claude call (or rules) verifies the draft reply against the ticket and the retrieved docs, and flags low confidence, billing disputes, or anything the docs do not cover. Flagged tickets are routed to a human queue instead of calling save_reply.
6. Call save_reply(ticket_id, text) exactly once, only after the plan, the draft, and the check have all passed, and make it idempotent per ticket_id so retries do not create duplicate replies. Wrap model calls with timeouts, retry limits, and a maximum number of steps so the agent cannot loop.
7. Update app/api.py so POST /triage returns the plan, category, draft reply, and whether it was routed to a human, and log the plan and each step (without secrets) for debugging. Keep ANTHROPIC_API_KEY and other settings in config.py, read from environment variables.
8. Write pytest tests in tests/ using a mocked Claude client: plan validation, correct category routing for sample billing/bug/how-to tickets, that save_reply is never called when the plan or check fails, that it is called once on success, and that the step limit stops runaway loops. Run the suite and try a few real tickets before deploying the single container.
