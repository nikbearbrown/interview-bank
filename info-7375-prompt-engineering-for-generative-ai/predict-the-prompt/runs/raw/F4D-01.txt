1. Define the routing contract first: a fixed label set (billing / bug / how-to / escalate-to-human), a Pydantic schema for the agent's structured output (label, confidence, short rationale, next_action), and a hard cap on loop iterations so the agent cannot run forever.
2. Add a new module app/router.py with a small tool set the Claude agent can call: classify_ticket, search_docs (keyword lookup over the 40 markdown articles, loaded once at startup), draft_reply, and save_reply(ticket_id, text) wrapped so it is only reachable after a passing check.
3. Implement the agent loop with the Anthropic SDK tool-use API: send the ticket plus a system prompt, execute whichever tool Claude requests, and append the tool_result to the message history before the next call.
4. Build the reflection step into the loop: after every tool result, make a separate short Claude call (or a required "reflect" tool call) that asks "does this result answer what I needed, is it consistent with the ticket, and what is the next step?" and returns a structured verdict of proceed, retry with a changed input, or escalate. Log each reflection with the step number.
5. Gate the database write: before save_reply runs, a final reflection checks the draft against the retrieved docs and the ticket (no invented policies, correct category, no secrets or other customers' data); on failure the agent revises once, then routes to a human queue instead of saving.
6. Wire it into POST /triage in app/api.py in place of the single-shot call, returning the label, the reply, and the reflection trace; keep timeouts, a per-ticket token budget, and retry-with-backoff for API errors, with the API key read from an environment variable via config.py.
7. Write pytest tests with the Claude client mocked: a clean billing ticket passes in one pass, a bad first search triggers a retry, a failed final check never calls save_reply, and the iteration cap forces escalation.
8. Evaluate on a small hand-labelled set of past tickets, comparing label accuracy and reply quality with and without reflection, and record the extra latency and token cost per ticket before deciding on defaults.
