1. Define the routing contract first: a small fixed set of destination queues (billing, bug, how-to, plus an explicit "needs human" fallback) and a structured result schema (category, confidence, reason, suggested queue) that Claude must return, so every step's output can be checked mechanically.
2. Extend app/triage.py with a route_ticket step that calls Claude with the ticket text and the queue definitions, requesting that structured output, and add the queue list and confidence threshold to config.py (secrets stay in environment variables).
3. Add a reflection step: after each result, make a second Claude call that receives the ticket, the proposed routing, and the reason, and critiques it (is the category supported by the ticket text, is anything ambiguous, is the draft reply consistent with the routing), returning accept / revise / escalate with a short justification.
4. Wrap the steps in a bounded loop in triage.py: classify, reflect, and if the verdict is revise, re-run classification with the critique added to the prompt; cap it at two or three iterations, and route to "needs human" if the cap is hit or confidence stays below the threshold.
5. Ground the reflection in the docs/ help articles by selecting a few relevant articles (simple keyword or embedding-free retrieval over the 40 files, limited to a token budget) and passing them to the reply-drafting and reflection calls, so the agent checks claims against real help content instead of guessing.
6. Make side effects safe: only call save_reply(ticket_id, text) once, after the final accepted or escalated decision, never inside the loop, and make it idempotent per ticket_id so retries and repeated POST /triage calls cannot write duplicate or half-reflected replies.
7. Expose the result through POST /triage in app/api.py, returning the final category, queue, reply, and a trace of each step's reflection verdict, with handling for API errors, timeouts, and malformed model output (retry once, then fall back to "needs human").
8. Add pytest tests in tests/ that stub the Claude client: clear tickets accepted on the first pass, an ambiguous ticket that gets revised, a loop that hits the iteration cap and escalates, malformed output, and a check that save_reply is called exactly once; then run the suite and a few real sample tickets to tune the threshold and prompts.
