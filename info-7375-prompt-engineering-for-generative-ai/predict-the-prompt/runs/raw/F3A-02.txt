Keep the existing flow and safety intact: classification step unchanged, save_reply(ticket_id, text) still called once per ticket with the final reply, and a no-match fallback (low retrieval score) that drafts a generic holding reply or marks the ticket for human review instead of letting Claude guess.

Add pytest tests: unit tests for chunking and ranking using a few fixture markdown files, a test that the prompt built for a ticket contains the expected article and instructions, a no-match test that triggers the fallback, and an API test of POST /triage with the Claude client and save_reply mocked so no network or database writes happen.

Check quality and rollout: run a small set of real or representative tickets per category against the docs, compare replies to the cited articles for groundedness, tune k, chunk size and score threshold, then log which articles were retrieved per ticket so wrong answers can be traced, and ship in the same container.
