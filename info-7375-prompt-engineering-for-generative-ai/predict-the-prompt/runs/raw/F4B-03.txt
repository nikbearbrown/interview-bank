1. Define the agent's contract: input is a ticket (id and text), output is a routing decision (billing / bug / how-to, or escalate to a human) plus the saved reply. Because the agent must act step by step with no separate planning step, decide up front that it will be a ReAct-style loop, where each turn Claude picks one next action from the tools and sees the result before choosing the next, with no upfront plan call.
2. Define a small set of tools as Anthropic tool-use schemas: search_docs (keyword lookup over the 40 markdown articles in docs/), classify_ticket (records the category and a confidence), save_reply (wraps the existing save_reply(ticket_id, text) database write), and escalate_to_human. Keep each tool narrow, with clear descriptions and typed inputs, and keep the docs lookup returning short excerpts rather than whole 600-word articles.
3. Write the system prompt: state the goal, the routing categories, when each tool applies, and when to stop (after save_reply or escalate_to_human). Instruct the model to take one action at a time and reason briefly from the latest observation, and do not include any instruction to write a plan first.
4. Implement the loop in a new module (for example app/router_agent.py) using the Anthropic Python SDK: send the messages with the tools, execute each tool_use block, append the tool_result, and repeat until the model ends its turn or calls a terminal tool. Add a hard step cap (for example 6 turns), per-call timeouts, and a safe fallback to escalate_to_human when the cap is hit or the SDK raises an error.
5. Add guardrails around the one side effect: save_reply may run only once per ticket, only after a category has been recorded, and with idempotency on ticket_id so retries cannot write duplicate replies. Validate tool inputs, truncate or sanitize ticket text, and treat ticket content and doc excerpts as untrusted data so they cannot override the system prompt.
6. Wire it in: have POST /triage in app/api.py call the agent (keeping the existing request and response shape), and have app/triage.py expose the tools. Read the model name, step cap, and API key from config.py and environment variables, and log each step (tool, arguments summary, latency, token use) for debugging.
7. Test with pytest using a fake or mocked Anthropic client that returns scripted tool_use sequences. Cover a billing ticket, a how-to ticket answered from docs, a bug ticket, a model that loops past the step cap, malformed tool arguments, and a duplicate save attempt, and assert that save_reply is called exactly once in the normal paths.
8. Evaluate before shipping: run a small labeled set of sample tickets against the real model in a gated, non-default test, and compare routing accuracy and average step count against the current single-call classification. Then confirm the container still builds with no new services, and release behind a config flag so the old path can be restored quickly.
