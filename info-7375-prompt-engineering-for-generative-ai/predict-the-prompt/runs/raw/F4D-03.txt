1. Define the agent's scope: for each ticket it runs a loop of observe, act, reflect, then decide the next step, with a hard cap (for example 6 iterations) and a clear stop condition, in a new module app/agent.py that app/api.py's POST /triage calls instead of the single-shot path.
2. Give Claude a small set of tools via the Anthropic SDK tool-use API: classify_ticket (billing / bug / how-to), search_docs (keyword lookup over the 40 markdown articles in docs/, loaded once at startup), draft_reply, and route_ticket. Keep save_reply out of the model's tools so the database write happens only in code the model cannot trigger directly.
3. Write the system prompt so that after every tool result Claude must emit a short structured reflection (what the result showed, whether it is sufficient or contradicts earlier findings, confidence, and the single next action) before it may call another tool. Parse this reflection as JSON so the loop can read it rather than trusting free text.
4. Implement the loop in code: send the conversation, execute any requested tool, append the tool result, then require the reflection; stop when Claude chooses "finish", when confidence is high, when the iteration cap or a token budget is reached, or when two consecutive reflections show no progress, and fall back to "needs human review" in those last cases.
5. Add guardrails around reflection: validate the classification against the allowed labels, require the reply to cite a docs article it actually retrieved, and run one final self-check pass comparing the draft reply to the ticket before routing, with a low-confidence result sending the ticket to a human queue rather than saving.
6. Call save_reply(ticket_id, text) exactly once at the end, only for an approved final result, and make it idempotent per ticket_id so retries or a repeated POST /triage never write duplicates; handle SDK errors, timeouts and malformed tool output with bounded retries.
7. Log each step's tool call, result and reflection (without secrets or full customer text beyond what is needed), and put the model name, iteration cap and thresholds in config.py with the API key read from an environment variable.
8. Add pytest tests in tests/ using a stubbed Anthropic client with scripted responses: a happy path, a reflection that triggers a second search, a loop that hits the cap, malformed reflection JSON, and a check that save_reply is called once; then run the suite and try a few sample tickets by hand.
