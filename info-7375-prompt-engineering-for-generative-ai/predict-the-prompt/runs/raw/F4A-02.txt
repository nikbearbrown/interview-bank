1. Define the agent's contract: a ticket comes in via POST /triage, and the agent must produce a category (billing / bug / how-to), a drafted reply, and a saved reply. Write down the allowed actions (classify, search docs, draft, save_reply) and treat save_reply as the only side-effecting step.
2. Add a planning stage in app/triage.py: before any action, call Claude once to produce a structured plan (JSON via the Anthropic SDK) listing the category guess, which of the 40 docs/ articles it needs, and the ordered steps. Validate the plan against a schema and the allowed-action list; reject or retry with an error message if it is malformed or proposes an unknown action.
3. Build read-only tools for the plan to use: a docs lookup that finds relevant articles in docs/ (keyword or small index, loading only the few needed since each is about 600 words), and keep the plan's references to docs limited to files that exist.
4. Write an executor loop that runs the validated plan step by step, calling Claude for classification and drafting with the retrieved docs as context. Cap the number of steps and tokens, and have the executor check each result against the plan, replanning once if a step fails or the classification contradicts the plan.
5. Gate the write: only call save_reply(ticket_id, text) after a final check step (reply non-empty, matches the category, grounded in retrieved docs), and make it idempotent per ticket_id so retries cannot save duplicates. If checks fail, return the draft flagged for human review instead of saving.
6. Wire it into app/api.py: POST /triage runs plan then execute, returns the category, reply, and the plan trace in the response, with timeouts and clear error handling for Anthropic API errors. Add model name, step limits, and the API key (from environment variables) to config.py.
7. Add pytest tests in tests/ with the Anthropic client mocked: plan schema validation, rejection of bad plans, each category path, replanning on failure, and that save_reply is called exactly once on success and never on a failed check.
8. Log each plan and step outcome for debugging without logging secrets or full ticket text, run the test suite, and try a few sample tickets of each type in the single container before shipping.
