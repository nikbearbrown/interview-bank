1. Define the agent's job and its allowed actions: for each ticket, a loop of small steps (classify, look up relevant docs, draft reply, check reply, route/save), implemented in app/triage.py with the Anthropic SDK using Claude tool use, so every step is a named tool call with a typed result.
2. Give Claude a small tool set: classify_ticket (billing / bug / how-to, with a confidence value), search_docs (keyword search over the 40 markdown articles in docs/, returning only the top few passages rather than whole articles), draft_reply, and save_reply(ticket_id, text). Keep save_reply as the only tool with a side effect, and gate it so it cannot be called until the checks pass.
3. After every tool result, add an explicit reflection step: ask Claude to write a short structured note (JSON fields such as "what_i_learned", "is_result_sufficient", "problems", "next_action") before it chooses the next step. For example, if search_docs returns weak or off-topic passages, the reflection should say so and trigger a refined query instead of drafting on thin evidence.
4. Make the reflection grounded rather than self-congratulating: check the draft reply against the retrieved doc passages and the original ticket text, and require each factual claim in the reply to cite a passage. Where the classification confidence is low or the category disagrees with the reply content, reroute or escalate to a human rather than guess.
5. Bound the loop for cost and safety: set a maximum number of steps (for example 6), a token budget per ticket, and a retry limit on repeated identical tool calls. Add timeouts and handle SDK errors and rate limits with backoff, so the agent always ends in a final state of either "saved", "needs human review" or "failed".
6. Wire it into POST /triage in app/api.py: validate input, run the agent loop, return the category, reply, and a trace of the steps and reflections. Persist the trace alongside the reply (or log it) so a person can see why a ticket was routed the way it was, and read the API key and model name from config.py environment variables only.
7. Write pytest tests in tests/ with the Claude client mocked: scripted tool results for a clean billing ticket, a bug ticket with poor first search results (reflection must trigger a second search), a low-confidence ticket (must escalate), and a runaway loop (must stop at the step cap). Assert that save_reply is called exactly once, and only after the checks pass.
8. Evaluate on a small hand-labelled set of real-style tickets, comparing the reflecting agent with the current single-pass triage on classification accuracy, reply groundedness, latency and token cost. Keep the reflection step only where it measurably helps, then deploy in the same container behind a config flag so we can roll back quickly.
