1. Define the agent's contract first: a ticket goes in; a classification (billing / bug / how-to), a drafted reply, and a routing decision come out, with a hard cap on steps and a fixed list of allowed actions. Write this as a short spec so every later step can be tested against it.
2. Break the work in `app/triage.py` into small named tools the agent can call: `classify_ticket`, `search_docs` (over the 40 help articles in `docs/`), `draft_reply`, and `save_reply`. Keep `save_reply` as the only write, and make it the last action, never one the agent can repeat freely.
3. Build the agent loop with the Anthropic SDK tool-use API in a new module (for example `app/agent.py`). Each turn, Claude picks one tool, the code runs it, and the result goes back as a tool_result message; stop on a final answer or when the step cap is reached.
4. Add the reflection step: after every tool result, make a separate Claude call (or a required reflection field) that asks "Does this result answer what was needed? Is it consistent with the ticket? What should happen next?", and returns a structured verdict (continue / retry with a change / escalate to a human). Feed that verdict into the next turn instead of letting the agent proceed blindly.
5. Make reflection decide the risky moves: before `save_reply`, require a reflection check that the category fits the ticket, the reply is grounded in the retrieved docs, and nothing is invented. If the check fails, allow a bounded number of redraft attempts, then route to a human queue rather than saving a bad reply.
6. Handle failures and cost: catch API errors, malformed tool arguments, and empty doc searches, and let the reflection step see these errors as results. Keep the loop idempotent so a retry never writes the same reply twice, and load the API key only from the environment via `config.py`.
7. Wire it into `app/api.py` so `POST /triage` calls the agent, and return the category, the reply, and a short trace of the steps and reflections (log the trace for debugging). Keep the old single-call path behind a setting so it can be switched back quickly.
8. Test with pytest using a stubbed Claude client: scripted cases for each category, a case where reflection triggers a retry, a case that hits the step cap and escalates, and a check that `save_reply` is called exactly once. Run a small set of real sample tickets by hand to compare quality and cost against the old path before shipping the container.
