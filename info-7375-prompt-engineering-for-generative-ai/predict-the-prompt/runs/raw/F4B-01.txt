Define the agent's tools as Anthropic SDK tool schemas in a new module under app/: classify_ticket (billing / bug / how-to), search_docs (keyword lookup over the 40 markdown articles in docs/), draft_reply, save_reply (wrapping the existing save_reply(ticket_id, text) database write), and route_ticket (assign the ticket to a queue).
2. Write a short system prompt that tells Claude to act one step at a time: read the ticket, call a tool, look at the result, then decide the next call. It gets no upfront plan or task decomposition, and no separate planning call.
3. Implement the loop in app/agent.py as a plain ReAct-style loop on the Messages API. Send the ticket and tool list, run each tool_use block Claude returns, append the tool_result to the messages, and repeat until Claude replies with end_turn.
4. Add guardrails: a maximum iteration count (for example 8), a per-call timeout, tool errors returned to Claude as is_error results instead of raised, and a check that save_reply runs at most once per ticket_id so retries cannot write duplicate replies.
5. Put the model name, max iterations and token limits in config.py, and read ANTHROPIC_API_KEY from the environment. Keep the doc index small enough to load once at startup.
6. Wire the agent into app/triage.py, or add it beside the existing path, and have POST /triage in app/api.py call it, returning the category, the routing decision and the saved reply. Keep the response shape the same so current callers do not break.
7. Add pytest tests in tests/ that stub the Anthropic client with scripted tool_use sequences. Cover the happy path for each category, a tool error, hitting the iteration limit, and the single-save rule. Add a small manual check against a few real example tickets.
8. Add logging of each step (tool name, inputs, result size, token usage) so runs can be audited. Rebuild the single container and confirm the test suite passes before deploying.
