1. Define the routing contract first: a fixed label set (billing / bug / how-to, plus an "unsure" escape hatch), a Pydantic model for the structured result (label, confidence, short rationale, next action), and the explicit steps the agent may take (classify, retrieve doc, draft reply, route, save_reply, escalate to human).
2. Refactor app/triage.py into a small explicit loop in plain Python with the Anthropic SDK: each iteration the model proposes one step through tool use (forced structured output), my code executes it, and the result goes back into the message history. Cap the loop at a fixed number of steps and a token budget, and put the model name, limits and thresholds in config.py (secrets stay in environment variables).
3. Add the reflection step after every tool result: a separate short Claude call (or a dedicated turn with its own prompt) that sees the ticket, the step taken and its result, and must return a structured verdict: ok / retry with a changed approach / escalate, with a one-line reason. The loop only proceeds to the next step on "ok", so a bad classification or a poor doc lookup gets caught before it feeds the next step.
4. Implement the tools: classify (returns label and confidence), find_docs (keyword search over the 40 markdown articles in docs/, loaded once at startup, no new service needed), draft_reply (grounded in the retrieved articles and told to cite them), and route/escalate. Keep save_reply as the only write and make it a gated final step that cannot run until the reflection on the drafted reply passes.
5. Make the write safe: save_reply is idempotent per ticket_id (upsert, not insert), runs only once at the end, and is never called on a retried or escalated path without an explicit "approved" verdict. Low confidence, repeated reflection failures, or hitting the step cap route the ticket to a human queue with the trace attached instead of saving a guessed reply.
6. Wire it into POST /triage in app/api.py: keep the existing request shape, return the label, the reply, the route and a compact trace of steps and reflection verdicts, and handle API errors, timeouts and rate limits with bounded retries, so the endpoint always returns a clean result or an explicit escalation.
7. Write pytest tests with the Anthropic client mocked: happy path, a reflection that rejects the first classification and triggers a retry, step-cap exhaustion, escalation on low confidence, malformed structured output, and a check that save_reply is called exactly once and only after approval. Add a small labeled set of sample tickets as a regression check that can optionally run against the live API.
8. Log each step, reflection verdict, token usage and latency per ticket (never secrets or raw customer data beyond what is needed), check the added reflection calls against cost and latency targets, and ship it in the same container behind a config flag so I can compare against the old single-call path before making it the default.
