1. Define the search tool contract: a `search_articles` tool schema (name, description saying when to use it, input `query` string, optional `max_results`) passed in the `tools` list of the Anthropic SDK call in `app/triage.py`. Keep it read-only so it has no side effects.
2. Build a small retrieval module (e.g. `app/articles.py`) that loads the 40 markdown files in `docs/` once at startup, splits them into chunks by heading, and returns the top few chunks for a query using simple keyword/BM25 scoring in pure Python. Each result carries the article filename, title, and chunk text so the reply can cite it.
3. Update the drafting call in `app/triage.py` to run a tool-use loop: send the ticket, and while the response has `stop_reason == "tool_use"`, execute each requested `search_articles` call, append the `tool_result` blocks, and call Claude again. Cap the loop at a few iterations and return a safe fallback if the cap is hit.
4. Rewrite the system prompt so Claude must search the articles before drafting, answer only from the returned text, cite the article it used, and say it cannot find an answer (suggesting escalation to a human) when searches return nothing relevant. Keep classification (billing / bug / how-to) separate from the drafting step.
5. Keep `save_reply(ticket_id, text)` outside the tool loop: only call it once, after the final text reply is produced, and never expose it to Claude as a tool. Handle tool errors by returning an error `tool_result` so Claude can retry or fall back.
6. Add settings to `config.py` (articles directory, max search results, max tool iterations, model name); secrets such as the API key stay in environment variables and nothing new is added to the container beyond bundling `docs/`.
7. Write pytest tests in `tests/`: unit tests for chunking and search ranking against fixture articles, and tests of the triage loop with the Anthropic client mocked to emit a `tool_use` then a final answer, asserting the tool result is fed back, the loop cap works, and `save_reply` is called exactly once with the grounded reply.
8. Verify end to end by running a handful of real tickets against the `POST /triage` endpoint, checking that replies cite the right articles and that unanswerable tickets get the "not found" response, then tune chunk size and the prompt based on the results.
