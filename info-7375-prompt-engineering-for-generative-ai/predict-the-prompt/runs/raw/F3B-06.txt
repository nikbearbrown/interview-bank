1. Estimate the size first: 40 articles at about 600 words each is roughly 24,000 words, around 32,000 to 35,000 tokens, which fits comfortably in Claude's context window. Confirm this by counting tokens with the Anthropic SDK's token-counting call on the concatenated docs, and record the number so any future growth is caught.
2. Add a loader in app/triage.py (or a small helper module) that reads every markdown file in docs/ in sorted order and builds one block of text, wrapping each article in a tag that carries its filename and title, for example a documents section with one document element per article. Load it once at startup and cache it, so the container does not re-read the files on every request.
3. Build the system prompt in app/triage.py as two parts: the stable instructions (role, classify as billing / bug / how-to, write the reply only from the articles, say so and flag for a human when the articles do not cover the question, cite the article used) and the full article block. Put the articles before the ticket-specific content, and keep the ticket text in the user message only.
4. Turn on prompt caching for the system prompt by marking the article block with a cache_control breakpoint in the Anthropic SDK call. Every ticket then reuses the same roughly 35,000-token prefix at the cached rate instead of paying full price and latency each time; keep the prefix byte-identical between calls so the cache hits.
5. Update the reply-drafting call so it asks for structured output (category, drafted reply, the article filenames it relied on, and a flag for when no article applied), and parse that before calling save_reply(ticket_id, text). If the model reports no matching article, save the draft marked as needing review rather than presenting an invented answer as final.
6. Put the model name, the docs path, and the cache setting in config.py, with the API key still read from environment variables. Make the loader fail clearly at startup if docs/ is empty or missing, since the container ships with the docs folder.
7. Add pytest tests with the Anthropic client mocked: the loader returns all 40 articles in a stable order, the system prompt contains every article and the cache marker, the ticket text is only in the user message, and the no-matching-article path flags the reply. Add a small test set of real-looking tickets with known answers in specific articles to check that the cited article is the right one.
8. Run the tests, then try several sample tickets through POST /triage against the real API and check the replies for accuracy against the articles, the cache read counts in the response usage data, and latency. If the corpus grows well past this size, revisit retrieval instead of stuffing everything in.
