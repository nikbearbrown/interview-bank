1. Define the agent's loop and its tools in a new module (e.g. app/agent.py) using the Anthropic Python SDK tool-use API: a small, fixed tool set such as lookup_docs (search the 40 help articles), classify_ticket, draft_reply, and save_reply, with a hard cap on the number of turns and a clear stop condition.
2. Write the system prompt so that after every tool result the model must emit a short structured reflection (what the result showed, whether it is good enough, what to do next, or whether to escalate) before choosing the next action. Keep the reflection in a dedicated field or tool call so it can be logged and checked, not buried in free text.
3. Implement the docs lookup as a simple keyword or embedding-free search over the markdown files, returning only the few most relevant passages so the 600-word articles do not flood the context.
4. Add guardrails in code around the reflection step: if the reflection says the classification is low-confidence, the draft contradicts the retrieved docs, or the retrieval was empty, route back to re-search or re-classify, or hand the ticket to a human, rather than continuing.
5. Make save_reply the final, gated action: it runs only after the reflection step approves the draft, only once per ticket, and never on a retry loop, since it is a database write; validate ticket_id and the text before writing.
6. Wire the agent into POST /triage in app/api.py, keeping the existing response shape, and add settings to config.py (model name, max turns, timeouts) with the API key read from the environment.
7. Add pytest tests with a stubbed Claude client: a happy path per category (billing / bug / how-to), a case where reflection forces a retry, a case that hits the turn cap and escalates, and a check that save_reply is called exactly once or not at all.
8. Log each step and its reflection (without secrets or customer personal data), run the tests, and try a handful of realistic tickets end to end to check cost, latency, and that the reflection actually changes behaviour.
