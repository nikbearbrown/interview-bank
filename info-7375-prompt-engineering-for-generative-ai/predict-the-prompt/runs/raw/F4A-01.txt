1. Define the agent's contract: input is a ticket (id and text), output is a structured result (category: billing / bug / how-to, a drafted reply, and a confidence or "needs human" flag). Keep the existing POST /triage shape so callers do not change.
2. Split the work into a planning call and an execution phase in app/triage.py. First ask Claude, with no database access, to produce a short structured plan (JSON validated with Pydantic) listing the steps it intends to take for this ticket, such as classify, look up relevant help articles, draft, self-check.
3. Validate the plan in plain Python before anything runs: only allow known step names from a fixed allowlist, cap the number of steps, and reject or fall back to a default plan if the output is malformed.
4. Execute the approved steps one at a time, each as its own Claude call with a narrow prompt: classify the ticket, retrieve the most relevant docs/ articles by simple keyword or embedding match (loaded once at startup, since the 40 articles are small), then draft the reply grounded in those articles.
5. Add a verification step before acting: a second Claude call (or rule checks) reviews the draft against the ticket and the retrieved articles for wrong claims, tone, and leaked secrets; if it fails, redraft once, then mark the ticket for human review instead of saving.
6. Gate the only side effect: call save_reply(ticket_id, text) exactly once, only after the plan was followed and verification passed, and make it idempotent per ticket_id so retries cannot write duplicates. Log the plan, each step result, and the final decision for auditing.
7. Handle failures and limits in config.py and app/api.py: read the API key from the environment, set model name, timeouts, retry with backoff, and a step/token budget; return clear HTTP errors from POST /triage and never save on partial failure.
8. Write pytest tests with the Anthropic client mocked: a valid plan runs end to end and saves once; a malformed or disallowed plan falls back safely; a failed verification does not call save_reply; retries do not double-write. Then update docs only if the API response shape changed, and ship in the same single container.
