1. Define the agent's job and tools: a Claude tool-use loop in a new `app/agent.py` with a small set of tools (classify_ticket, search_docs over the 40 help articles, draft_reply, save_reply), keeping `save_reply` as the only database write. Cap the loop at a fixed number of steps so it cannot run forever.
2. Add a reflection step after every tool result: before choosing the next action, the model must write a short structured note (JSON via a tool-use schema) stating what the result showed, whether it is good enough (confidence, any contradiction or missing information), and what to do next. Keep this note in the conversation history so later steps can see it.
3. Write the system prompt to define the three categories (billing / bug / how-to), the reflect-then-act rule, and when to stop or escalate to a human instead of guessing. Include a few examples of a reflection that changes course, such as a low-confidence classification leading to a doc search before drafting.
4. Implement docs retrieval simply: load the 40 markdown articles at startup, split them into sections, and have search_docs return the top few matching sections (keyword or embedding ranking). Reflection should check whether the retrieved text actually answers the ticket, and re-query with different terms if it does not.
5. Gate the write: allow `save_reply` only after a final reflection confirms the category is set, the draft is grounded in the retrieved docs, and no unsupported promises (refunds, dates) appear. If the checks fail after a set number of retries, route the ticket to a human-review status instead of saving an automated reply.
6. Wire it into `app/triage.py` and `POST /triage` in `app/api.py`, returning the category, the reply, and the reflection trace so decisions can be audited. Add settings in `config.py` for model name, max steps, and retry limits, with the API key read from an environment variable.
7. Write pytest tests with a mocked Anthropic client: a clean ticket reaches save_reply in the expected steps, a low-confidence reflection triggers a re-search, a failed check escalates without writing, and the step cap holds. Add a small set of labeled sample tickets for checking classification accuracy.
8. Add logging of each step's tool call, reflection, token use, and latency, then run the tests and a handful of real tickets to tune the prompt and the thresholds. Note in the docs that reflection adds extra model calls per ticket, so cost and latency go up.
