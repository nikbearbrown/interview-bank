1. Define the retrieval need: the 40 markdown articles in `docs/` (about 600 words each) are too many to paste into every prompt, so Claude will fetch only the ones relevant to each ticket through a tool.
2. Build a small index module (e.g. `app/docs_search.py`) that loads `docs/*.md` at startup, splits each article into sections, and exposes `search_docs(query, k=3)` using simple keyword/BM25 scoring in plain Python, plus `get_article(name)` to return a full article. Keep it dependency-light since the service is a single container.
3. Declare the tool(s) for the Anthropic SDK: a `search_help_articles` tool with a JSON input schema (`query` string, optional `limit`) and a clear description telling Claude to use it before answering any factual question about product behavior.
4. Update `app/triage.py` to run a tool-use loop with `client.messages.create(..., tools=[...])`: when the response has `stop_reason == "tool_use"`, run `search_docs`, append the `tool_result` message (including article names and text), and call Claude again until it returns a final answer. Cap the loop at a few iterations and handle tool errors by returning an error `tool_result`.
5. Revise the system prompt so the reply is grounded in the retrieved articles: cite the article used, do not invent policies, and say it will escalate to a human if the search returns nothing relevant. Keep classification (billing / bug / how-to) as a separate structured output.
6. Keep the database write unchanged and outside the tool loop: `save_reply(ticket_id, text)` is called by `triage.py` only once with the final drafted reply, never exposed to Claude as a tool, so retries cannot create duplicate writes.
7. Add pytest tests in `tests/`: unit tests for the search function against fixture articles, and a triage test with the Anthropic client mocked to return a `tool_use` turn then a final text turn, asserting the tool result is passed back and `save_reply` is called once. Add a no-results case.
8. Check config and deployment: add settings to `config.py` (docs path, result limit, max tool iterations), keep the API key in the environment, make sure `docs/` is copied into the container image, and verify `POST /triage` end to end on a few sample tickets while logging which articles were retrieved.
