1. Decide the retrieval design first: with 40 articles of about 600 words each (roughly 32k tokens total), start with a simple, dependency-free retriever inside the existing container (no vector database or new service), and put it behind a small interface so it can be swapped later.
2. Add a `app/kb.py` module that loads the markdown files from `docs/` at startup, splits them into chunks by heading (keeping article title and filename as metadata), and builds an in-memory index (BM25-style keyword scoring first; optionally Claude-free embeddings later only if keyword recall proves poor).
3. Implement `retrieve(ticket_text, k=3)` that returns the top-k chunks with their article IDs, plus a minimum score threshold so tickets with no relevant article return an empty result instead of weak matches.
4. Change the reply-drafting call in `app/triage.py` to include the retrieved chunks in the prompt, wrapped in clearly delimited tags with article IDs. Instruct Claude to answer only from those excerpts, cite the article ID it used, and say it cannot find an answer (flagging the ticket for a human) when the excerpts do not cover the question. Keep the classification call separate and unchanged, and treat ticket text and article text as data, not instructions.
5. Keep `save_reply(ticket_id, text)` as the only write, and have the drafter return structured output (reply text, cited article IDs, a "grounded" flag) so the saved reply and its citations are validated before the database write happens; if the model returns no valid citation, save it as a needs-human-review draft.
6. Put settings such as `k`, the score threshold, and the docs path in `config.py`, and do the document load once at app startup rather than per request; no new secrets are needed.
7. Add pytest tests for the retriever (known ticket text returns the expected article, off-topic text returns nothing, chunking and loading work) and for `triage.py` with the Anthropic client mocked (retrieved excerpts appear in the prompt, a reply with no citation is flagged, `save_reply` is mocked and called once).
8. Check quality on a small set of sample tickets covering billing, bug and how-to, comparing grounded replies against the articles by hand, then adjust chunk size, `k`, and the threshold; update the container build so `docs/` ships in the image, and log retrieved article IDs per ticket so bad answers can be traced.
