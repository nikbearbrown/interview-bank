1. Read app/triage.py, app/api.py, config.py and the existing tests/ to learn the function signatures, how the Anthropic client is created, and what fixtures or conventions pytest already uses there.
2. Decide the test boundaries: unit tests cover the classify-and-draft logic and the request handling, and never call the real Claude API or touch the real database. Anything that needs the network or a database write is replaced with a fake.
3. Put the Anthropic client behind a small seam, such as an injectable client parameter or a monkeypatched module-level client, so tests can substitute a stub that returns canned message objects shaped like the SDK's response (content blocks with text).
4. Write pytest cases for classification: one canned reply each for billing, bug and how-to maps to the right label. Also test the edge cases: label in different casing or with extra whitespace, an unexpected or unparseable label, an empty ticket, and an SDK exception such as a timeout or rate-limit error.
5. Write cases for reply drafting and saving: the drafted text from the stub is passed to a mocked save_reply with the correct ticket_id exactly once, and save_reply is not called when classification or the Claude call fails.
6. Write FastAPI tests with TestClient against POST /triage, with triage's Claude call and save_reply patched: a valid payload returns 200 and the expected body, a missing or empty ticket field returns 422, and an upstream failure returns the intended error status.
7. Keep secrets out of the tests by setting a dummy ANTHROPIC_API_KEY with monkeypatch.setenv, and test that config.py reads settings from environment variables and fails clearly when a required one is missing.
8. Run the pytest suite to confirm the new tests pass and run in milliseconds without network access. Then deliberately break the label mapping once to check that the tests actually fail, and fix any flaky or over-mocked tests.
