1. Define the routing contract first: a fixed set of categories (billing, bug, how-to, plus an "unclear/escalate" bucket), the routing action for each, and a Pydantic schema for the plan and for the final decision. Write this down before touching any code so the agent and the tests share one definition.
2. Add a planning stage in `app/triage.py` that makes a first Claude call which only produces a short structured plan (what the ticket is asking, which docs articles might matter, what action it intends, and what it is unsure about). This call has no side effects and its output is validated against the schema before anything else runs.
3. Add a plan-check step in plain Python between planning and acting: reject plans that pick an unknown category, skip the confidence field, or request an action outside the allowed list, and retry the planning call once with the validation error before falling back to the escalate bucket.
4. Execute the plan in a second stage: use the planned category and doc references to load only the relevant `docs/` articles into the prompt (not all 40), call Claude to draft the reply, and keep `save_reply(ticket_id, text)` as the last step so no database write happens until classification, plan, and draft have all passed validation.
5. Make the write safe: skip `save_reply` and flag the ticket for a human when confidence is low or the plan was escalated, and make the save idempotent per ticket_id so retries or duplicate requests cannot store two replies.
6. Update `app/api.py` so `POST /triage` returns the plan, the category, and the draft reply together, with sensible error responses for Claude API failures or timeouts, and take the API key and model name from `config.py` via environment variables.
7. Write pytest tests in `tests/` with the Anthropic client mocked: a valid plan per category, a malformed plan that triggers retry then escalation, a low-confidence case that must not call `save_reply`, and a check that the plan call happens before any save.
8. Run the tests and a handful of realistic sample tickets through the endpoint in the container, review the logged plans for mistakes, and tune the planning and drafting prompts based on what you see before shipping.
