1. Define the routing contract: a fixed set of queues (billing, bug, how-to, plus an "unsure/human" queue), and a small typed result object (queue, confidence, reasoning, cited doc names) that every Claude call must return as validated JSON.
2. Add a new module `app/router.py` that runs a loop per ticket: Claude proposes a route (step), then the code executes it, then a separate "reflect" Claude call reviews that result before the next step is allowed. Keep the loop bounded (for example, a hard maximum of 3 iterations) so it cannot run away on cost or time.
3. Give the agent a few narrow tools via the Anthropic SDK tool-use API: `search_docs` (looks up the relevant markdown articles in `docs/` by keyword, returning short snippets rather than whole 600-word articles), `classify`, and `draft_reply`. Do not expose `save_reply` to the model.
4. Write the reflection prompt so Claude critiques the last result against explicit checks (does the category match the ticket text, is the draft grounded in a retrieved doc, is anything promised that the docs do not support), then answers with a structured verdict: accept, revise with a stated reason, or escalate to human.
5. Make the database write deterministic and gated: only the surrounding Python code calls `save_reply(ticket_id, text)`, and only after the reflection verdict is "accept" on the final draft; escalations save nothing to the reply table and are flagged for a person. Make the write idempotent per ticket_id so a retry cannot double-save.
6. Wire the router into `app/triage.py` and `POST /triage` in `app/api.py` behind a config flag in `config.py`, so the old single-call path stays available for rollback; read the API key and limits (max iterations, model name, timeouts) from environment variables, and return the route, number of reflection rounds, and escalation status in the response.
7. Add pytest tests in `tests/` using a stubbed Claude client: a clean ticket accepted on the first pass, a ticket whose first draft is rejected and then fixed on revision, a ticket that hits the iteration cap and escalates, malformed JSON from the model, and a check that `save_reply` is never called on escalation or failure.
8. Build a small labelled set of sample tickets (including ambiguous and adversarial ones) and compare the reflecting agent against the single-call baseline for accuracy, escalation rate, and extra latency and token cost; log each step's input, output, and verdict with the ticket_id so failures can be inspected, then tune the reflection prompt and iteration cap from those results.
