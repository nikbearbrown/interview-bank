1. Define the agent's contract: input is a ticket, output is a routing decision (billing / bug / how-to, plus a drafted reply) saved via save_reply. Decide the loop is reactive, with no up-front planning call: at each turn Claude sees the ticket plus all prior tool results and picks only the next action.
2. Add a new module (e.g. app/router_agent.py) that runs a ReAct-style loop with the Anthropic SDK's tool-use API. Each iteration makes one messages.create call, executes any requested tool, appends the tool_result to the message list, and repeats until Claude returns a final answer.
3. Define a small set of tools with JSON schemas: search_docs (keyword search over the 40 markdown articles in docs/), classify_ticket (records the category and a confidence), and save_reply (wraps the existing database write). Keep save_reply as the only side-effecting tool.
4. Write the system prompt so the model acts one step at a time. It should say to look at what is known so far, take the single most useful next action, and not write out a multi-step plan. It should also say to call save_reply exactly once, only after it has classified the ticket and drafted a reply grounded in the docs.
5. Add guardrails in code, not in the prompt: a hard cap on iterations (e.g. 6), a token budget, a retry with backoff on API errors, and validation of tool arguments. If the cap is reached without a saved reply, fall back to the existing single-call triage path or flag the ticket for a human.
6. Wire the agent into app/api.py behind POST /triage, selected by a config.py setting (e.g. an AGENT_MODE flag), with the API key still read from the environment. Return the category, the reply and the number of steps taken so behavior can be observed.
7. Write pytest tests that mock the Anthropic client with scripted tool-use sequences. Cover the normal path, a ticket that needs a docs lookup, the iteration cap, a malformed tool call, and the guarantee that save_reply is called at most once.
8. Check quality on a small set of labeled sample tickets, comparing routing accuracy and steps per ticket against the current single-call version. Log each step's tool and result for debugging, then ship it in the same container behind the flag and enable it gradually.
