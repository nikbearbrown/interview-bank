1. Define the agent's tool set as Anthropic SDK tool schemas in app/triage.py: classify_ticket (billing / bug / how-to), search_docs (keyword lookup over the 40 markdown articles in docs/), draft_reply, and save_reply(ticket_id, text) wrapping the existing database write.
2. Write a short system prompt that tells Claude to act step by step: after each tool result, decide and call the single next tool, with no separate planning step or up-front plan, and to finish by calling save_reply once.
3. Implement a plain ReAct-style loop in app/triage.py using client.messages.create with tools: send the ticket, execute whichever tool_use block comes back, append the tool_result to the messages, and repeat until Claude returns a final answer with no tool call.
4. Add loop safeguards: a hard max-iterations cap (for example 8), a per-call token limit, a timeout, and handling of unknown tool names or malformed tool inputs by returning an error tool_result so the model can recover.
5. Make save_reply safe to call from an agent: enforce that it runs at most once per ticket_id (idempotent write), validate the text is non-empty, and keep it as the last step so a failed loop never leaves a half-written reply.
6. Keep search_docs lightweight and in-process (load docs/ at startup, return only the top few short excerpts rather than whole 600-word articles) to protect context size; read the API key from the environment via config.py and add a configurable model name.
7. Wire the loop into POST /triage in app/api.py, returning the category, the reply, and the list of steps taken (tool names called) so behavior can be inspected.
8. Add pytest tests in tests/ with a mocked Anthropic client: a scripted multi-step run (classify, search, draft, save), the iteration-cap path, a bad tool call recovery, and a check that save_reply is called exactly once; then manually try a few sample tickets.
