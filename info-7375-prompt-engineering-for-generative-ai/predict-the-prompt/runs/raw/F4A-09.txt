1. Define the routing contract first: the set of queues the agent can route to (billing, bug, how-to, plus an "escalate to human" fallback), what a routing decision must contain (queue, confidence, one-sentence reason, whether a reply draft is needed), and which actions are side effects (anything that calls save_reply or otherwise writes to the database) versus read-only.
2. Add a planning stage in app/triage.py that runs before any action: one Claude call (Anthropic Python SDK) that receives the ticket text and returns a structured plan as JSON (ordered steps, the queue it intends to pick, which help articles it expects to need, and what it is unsure about). Validate that JSON against a schema (for example with pydantic) and retry once or fall back to escalation if it is malformed.
3. Add a plan-check step between planning and acting: deterministic Python code that rejects plans using unknown queues, skipping the classification step, or calling save_reply with no drafted reply, and that routes low-confidence or ambiguous plans to the human fallback instead of acting. Keep this check in plain code, not a second model call, so it is cheap and testable.
4. Implement the execution stage as a small loop that carries out the approved plan one step at a time: classify, retrieve only the help articles named in the plan from docs/ (selecting by title or keyword rather than loading all 40 into the prompt), draft the reply with those articles as context, and only then call save_reply(ticket_id, text). If a step's result contradicts the plan (for example the classification differs from the planned queue), stop and re-plan once, or escalate.
5. Make writes safe and traceable: call save_reply exactly once per ticket and only after validation passes, make it idempotent on ticket_id so a retry cannot create duplicate replies, and log the plan, the executed steps and the final routing decision with the ticket id (without logging secrets or full customer text beyond what is needed).
6. Wire it into app/api.py by keeping POST /triage's request shape, returning the routing decision plus the plan summary in the response, and adding timeouts, a bounded retry on Anthropic API errors, and a clear error response; load the model name, retry limits, confidence threshold and the API key from config.py and environment variables.
7. Write pytest tests in tests/ using a mocked Anthropic client: one ticket per queue, a malformed plan, a plan that fails the check, a low-confidence ticket going to the fallback, a mid-run contradiction triggering re-plan, and an assertion that save_reply is never called when planning or checking fails.
8. Verify end to end by running the test suite and a handful of realistic sample tickets against the container locally, review the logged plans for sanity, then roll out behind a config flag so the old direct-triage path can be restored quickly if routing quality drops.
