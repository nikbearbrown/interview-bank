1. Define the agent's contract first: input is a ticket (id, text); output is a structured plan (classification billing/bug/how-to, proposed reply, proposed `save_reply` write, cited help articles) plus a status of pending, approved, rejected, or edited. Nothing that writes to the database may run in the planning phase.
2. Split `app/triage.py` into two Claude-backed phases using the Anthropic SDK: a planning call that returns the plan as JSON (validated with a schema, retried once on malformed output), and an execution call that runs only after approval. Give the planner read-only tools (for example, search of the 40 docs in `docs/`) and withhold any write tool from it.
3. Add a lightweight retrieval step for the help articles: chunk and index the `docs/` markdown at startup (keyword or embedding search, no new service, since we deploy one container), so the plan can cite the specific articles it will base the reply on.
4. Persist pending plans so approval can happen asynchronously: a small plans table (or SQLite file in the same container) holding ticket id, plan JSON, status, reviewer, timestamps, and a hash of the plan that was shown to the reviewer.
5. Extend `app/api.py`: `POST /triage` now only creates and returns a pending plan; add `GET /plans/{id}`, `POST /plans/{id}/approve` (optionally with edits), and `POST /plans/{id}/reject`. Protect the approval endpoints with a reviewer API key read from an environment variable via `config.py`, and make approval idempotent.
6. Implement execution in `app/triage.py`: on approval, verify the stored plan hash matches what was approved, then run the plan and call `save_reply(ticket_id, text)` exactly once with the approved or edited text. Reject a replay on an already-executed plan, and record the outcome.
7. Add guardrails: truncate and delimit ticket text as untrusted input to resist prompt injection, enforce a step limit and timeout on the planner, route low-confidence classifications to a human with no auto-suggested reply, and log every plan, decision, and write without leaking secrets.
8. Write pytest tests with the Claude client mocked: planner output schema validation, no `save_reply` call before approval, approve/reject/edit paths, replay and tampered-plan rejection, and API auth. Then update `docs/` or a README section describing the approval workflow and the new environment variables.
