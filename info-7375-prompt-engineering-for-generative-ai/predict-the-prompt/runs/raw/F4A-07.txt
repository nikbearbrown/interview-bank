1. Define the agent's contract first: input is a ticket (id plus text), output is a routing decision (billing, bug, or how-to, plus a confidence and a short reason) and an optional draft reply. Decide up front which actions are read-only and which are writes, since `save_reply` is the only database write and must never run before the plan is approved by the agent's own checks.
2. Add a planning stage in `app/triage.py` that makes a Claude call with no side effects. It returns a structured plan (JSON validated with a Pydantic model): the category, the evidence from the ticket, which of the 40 `docs/` articles to consult, and the exact actions it intends to take, in order.
3. Add an act stage that runs only the actions listed in the validated plan. Retrieval over `docs/` is done with a simple keyword or title lookup loaded at startup (no new service, since this is one container), and the selected articles are passed to a second Claude call that drafts the reply and sets the category.
4. Put a deterministic gate between plan and act: reject plans with an unknown category, a missing ticket id, or any step outside an allowed list, and send low-confidence or ambiguous tickets to a "needs human" outcome instead of calling `save_reply`. Call `save_reply` once, last, with the reply text, and make it idempotent per ticket id so retries cannot write twice.
5. Wire it into `POST /triage` in `app/api.py` with request and response models. Return the plan, the category, and the draft in the response so a reviewer can see why the ticket was routed that way, and map failures (invalid plan, Claude errors, timeouts) to clear HTTP errors.
6. Configure the model name, max tokens, timeouts, retry count, and confidence threshold in `config.py`, with the Anthropic API key read from an environment variable and never logged. Keep the ticket text and plan out of logs beyond the ticket id and category.
7. Write pytest tests in `tests/` using a stubbed Anthropic client: one ticket per category, a malformed plan, a low-confidence ticket, a plan that tries a disallowed step, and a retry that must not double-write. Assert that `save_reply` is called zero times on rejection and exactly once on success.
8. Run the full test suite, then try a small set of realistic tickets against the real API in a non-production environment, and compare the plans with the final actions to confirm the agent does what it said it would. Rebuild the container image and check that the endpoint starts and responds with only the environment variables set.
